Git no terminal

Esta página cobre o mínimo para trabalhar em equipa no repositório do GitHub. O git guarda o histórico do código e deixa duas pessoas editar os mesmos ficheiros sem se pisarem.

Conceitos

  • repositório (repo): a pasta do projeto com todo o histórico.
  • commit: um "save" com uma mensagem a dizer o que mudou.
  • push: envia os teus commits para o GitHub.
  • pull: traz do GitHub os commits dos outros.
  • branch: uma linha de trabalho separada. A principal chama-se main.

Configuração inicial (só uma vez)

Instala o git e diz-lhe quem és. O nome e email aparecem em cada commit.

git config --global user.name "O teu nome"
git config --global user.email "o.teu@email.com"

Precisas também de uma conta no GitHub e de ser adicionado ao repositório pelo otzpt.

Descarregar o projeto (só uma vez)

git clone https://github.com/otzpt/Maze_12MHZ
cd Maze_12MHZ

O ciclo do dia a dia

Faz sempre por esta ordem.

  1. Antes de começar, traz o trabalho mais recente: 
    git pull
  2. Edita os ficheiros que precisas.
  3. Vê o que mudou: 
    git status
  4. Escolhe os ficheiros a guardar: 
    git add ficheiro.ino
git add .          # todos os ficheiros alterados
  5. Guarda com uma mensagem curta e clara: 
    git commit -m "adicionado sensor de distancia"
  6. Envia para o GitHub: 
    git push

Comandos úteis

git status         # o que mudou e o que esta pronto para commit
git log --oneline  # lista dos ultimos commits
git diff           # ver as linhas alteradas antes do add

Conflitos

Se duas pessoas mudarem as mesmas linhas, o git pull pára e avisa de um conflito. Isto é normal e não estragou nada.

  1. Abre o ficheiro indicado. Vais ver isto: 
    <<<<<<< HEAD
a tua versao
=======
a versao do outro
>>>>>>> origin/main
  2. Apaga as linhas <<<<<<<, ======= e >>>>>>> e deixa só o código certo.
  3. Corre git add ficheiro e depois git commit.

Se não tiveres a certeza do que manter, pergunta ao outro antes de apagar.

Regras da equipa

  • Faz git pull sempre antes de começar a trabalhar.
  • Faz commits pequenos e frequentes, com mensagens que dizem o que mudou.
  • Não deixes código que não compila no main.
  • Avisa o outro quando vais mexer num ficheiro grande, para evitar conflitos.
  • Nunca uses git push --force. Apaga o trabalho dos outros.

Erros comuns

  • rejected ... fetch first no push: alguém enviou antes de ti. Faz git pull e depois git push outra vez.
  • Alterei um ficheiro sem querer: git restore ficheiro volta à última versão guardada. As alterações perdem-se.
  • Esqueci-me de um ficheiro no último commit: faz git add desse ficheiro e git commit de novo, com outra mensagem.
  • Não sei o que fiz: corre git status e lê o que diz. Se continuar confuso, pede ajuda antes de tentar outros comandos.
